# Navigasyon Mimarisi — Developer Yönergesi

> Bu belge, 175 HTML sayfasının 4 navigasyon bölgesine nasıl dağıtılacağını tanımlar.
> Gerekçeler UX ve kullanım sıklığı kriterlerine dayanmaktadır.

---

## Navigasyon Bölgeleri ve Kurallar

```
┌─────────────────────────────────────────────────────┐
│  TOPBAR                              [search] [+] [notif] [avatar▼]  │
├────────┬────────────────────────────────────────────┤
│        │                                            │
│  SB-1  │  SB-2 (aktif modülün alt menüsü)          │
│ (Rail) │                                            │
│        │  SAYFA İÇERİĞİ                             │
│        │                                            │
└────────┴────────────────────────────────────────────┘
```

**4 bölge:**
- **Sidebar 1 (SB-1)** — Dar/rail sidebar. Sadece ana modül ikonları.
- **Sidebar 2 (SB-2)** — Geniş sidebar. SB-1'de seçili modülün alt sayfaları.
- **Topbar** — Global araçlar. Workspace, arama, bildirim, oluştur.
- **Profile Menu** — Avatar dropdown. Kişisel + hızlı çıkış.
- **Settings Menu** — `settings.html` dahilindeki sekmeli yapı.

## Topbar — Global Araçlar

> **Kural:** Modülden bağımsız, her sayfada geçerli olan, **bağlam değiştiren veya anlık eylem** olan öğeler buraya girer.

```
[Workspace Switcher ▼]   [Global Search]   [+ Oluştur]   [Bildirim]   [Avatar ▼]
```

| Öğe | Açıklama | Bağlantı |
|-----|----------|----------|
| **Workspace Switcher** | Aktif workspace'i değiştir, workspace listesine git | `workspaces.html` |
| **Global Search** | Tüm sayfalarda arama | — (modal) |
| **+ Oluştur** | Hızlı oluşturma dropdown: Kampanya, Rapor, İçerik, Kural | Doğrudan `*-create.html` sayfaları |
| **Bildirim zili** | Bildirim paneli / drawer | `notifications.html` |
| **Avatar** | Profile menu açar | bkz. aşağıda |

**Gerekçe:** Workspace switcher topbar'da olmalı çünkü tüm sidebar içeriği workspace'e göre filtrelenir. Her sayfada erişilebilir olması gerekir. Bildirimler de modüle özgü değil, global.

## Settings Menu — `settings.html` İçi Sekmeler

> **Kural:** Yönetimsel, teknik kurulum, nadiren değiştirilen yapılandırmalar.
> Kullanıcı buraya amaçlı gelir; rastgele navigasyona ihtiyaç yok.

`settings.html` bir sekme paneli olarak çalışır:

```
Settings
├── [Genel]            → settings.html (varsayılan tab)
├── [Güvenlik]         → settings-security.html
├── [Webhooks]         → settings-webhooks.html
├── [Tenant Ayarları]  → settings-tenant-settings.html
├── [Schema]           → schema.html, schema-*.html
├── [Security/Site]    → security.html, security-*.html
├── [Performance]      → performance.html, performance-*.html
└── [Audit]            → audit.html, audit-detail.html
```

**Gerekçe:**
- `schema.*` — Yapısal veri kurulumu üretim değil, teknik konfigürasyon. Ara ara yapılan, metodolojik çalışma.
- `security.*` — SSL, header, zafiyet taraması. DevOps/teknik karar, günlük iş akışı değil.
- `performance.*` — Vitals, uptime, hız. Periyodik izleme; alert gelince bakılır.
- `audit.*` — Toplu tarama başlatma ve sonuç görüntüleme. Kampanya öncesi/sonrası yapılır.
- `settings-webhooks.html` — Entegrasyon / otomasyon kurulumu. Tek seferlik teknik iş.
